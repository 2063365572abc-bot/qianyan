# Qianyan 使用说明

当前版本：阿里云真实模型 + 平台收件箱。微信和公网部署暂缓。

## 进入平台

在运行项目的电脑上打开 http://localhost:5173。私人空间登录密码保存在本地 `.local/access.json`，不要分享或发布该文件。Demo 入口使用独立的样例空间，部署事件明确标为回放。

## 交代一个真实目标

进入“今日与目标”，选择“个人空间”，在对话中说：

> 帮我一直跟进一个目标：月底前准备好一次五分钟项目展示，先分成讲解提纲、演示检查、一次彩排三个任务。

系统保存原话、生成待确认草稿。选择新目标，检查任务、完成标准、依赖和绝对截止日期，再确认计划。模糊日期需要你补充；系统不会凭空猜日期。也可以用“交代一个目标”表单，手动填写与修改任务。

## 让它记住你

在“我的管家”设置称呼、风格、每天可用时间、时区、联系时段和主动跟进偏好。明确的自然语言指令也可使用：

> 请记住我每天只有两小时可以做项目。
>
> 以后只在下午提醒我。

“下午”按 12:00–18:00 保存，回复会说明时间窗口。可以在设置中改成精确时间。

在目标内保存的记忆只用于该目标；“个人空间”保存的记忆可用于多个目标。“长期记忆”支持修改与遗忘。顶部可导出自己的数据。

## 更新事实和主观进展

GitHub 连接后，Worker 自动观察仓库事实。文件存在不等于任务完成，系统会按已定义的完成标准核对。通过“进展证据”可以查看依据。

线下工作、主观认可和系统看不到的进展由你补充。明确确认某项任务时，可以在任务控制中标为完成，或发送：

> 确认完成：任务的完整名称

名称不明确时系统会请你选择任务，避免标错。完成整个目标则使用“确认目标完成”。

## 持续跟进

Worker 与网页分别运行。关闭网页后，电脑、数据库和 Worker 必须保持运行。重要变化、需要决定或需要行动的事项保存在“跟进收件箱”；普通 commit 不逐条提醒。当前版本不会向手机发微信。

收件箱支持查看依据、保持进行中、确认处理和稍后提醒。目标可暂停、恢复，计划更新可撤销。

## 遇到问题

- 计划生成失败：空草稿可重试生成，已有任务不会被悄悄覆盖。
- 模型不可用：已保存的计划、事实和手动控制仍可使用，页面显示失败原因。
- 来源同步失败：来源状态会提示异常，不将缺失信息当作完成证据。
- 重启电脑后：按根目录 `README.md` 重新启动 PostgreSQL、API、Worker 和前端，持久数据仍在。

实际试用时，请反馈“输入了什么、希望发生什么、实际出现什么”。当前机械验证记录在 `infra/platform-acceptance.md`；用户实际体验与真实跨日使用尚待验收。
