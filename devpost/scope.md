# Qianyan — 可定制的云端个人管家

一句话：**交代一次目标，Qianyan 记住你、维护计划、持续跟进，并在真正需要时主动找到你。**

依据用户确认的顺序：管家底座 → 一个完整场景验证 → 扩展生活接入。整套规划已批准，当前按该范围开发；实际验收证据见 checklist。

## The Unique Kernel

可控的个人记忆 + 证据支持的目标进展 + 后台主动维护下一步。个性化设置真正影响沟通、安排和联系时机；完成状态有依据，用户可以纠正判断。

## Who It's For

首先服务希望拥有自己的个人管家、需要持续推进多个个人事项的用户。黑客松参与者、独立开发者是第一条自动观察验证场景。底座可管理没有外部连接器的个人目标；这种目标的线下进展必须由用户补充。

核心痛点：聊天上下文易丢失；Todo 需要手动维护；提醒知道时间却不知道目标；用户忙别的事时没人跟进；自动助手难说明完成结论的依据。

## The Core Loop

设定管家和个人偏好 → 交代目标、期限、完成标准 → 形成可编辑计划 → 云端后台观察系统事实和内部状态 → 记录证据 → 更新计划、下一步和跟进时间 → 按通知规则联系本人 → 用户回复或纠正 → 记忆更新并继续跟进。

自主权限固定为 **Observe → Update plan → Create next action → Re-prioritize → Schedule follow-up**，加上用户授权的向本人通知。主观判断、线下进展与系统无法观测的信息由用户提供。

## Inspiration & Identity

对标 Muse 的个人化、长期记忆、持续后台工作和主动性，保留“贾维斯”式管家体验。使用简洁结果卡展示“Qianyan updated your plan”、依据、阻塞和下一步。不给用户主界面堆满 Agent 日志。

## Why This Matters to the Learner

用户希望完整做成项目、真实经历一次搭建。最终方向、功能和技术方案共同确认；规划阶段禁止正式项目代码。

## What "Working" Looks Like

用户设定称呼、沟通偏好、联系时段与权限，交代一个目标一次。关闭网页后后台仍运行，收到有行动价值的企业微信通知；通过回复或网页处理后计划变化。第二天重新打开，目标、已完成事项、阻碍、下一步和偏好仍在；纠正一条记忆后下一次处理使用新值。

自动观察验证：GitHub README 达到预定结构标准，系统记录证据并完成对应任务；如果 Installation 空白则保留未完成。Vercel 最新生产构建失败，管家自动优先安排排查部署并将录制任务移到部署成功之后。Commit 只增加证据，不触发无意义推送。

## The POC Boundary

**阶段一先做底座，阶段二完成比赛 MVP 的证据接入。** 先后顺序是用户选择；下面的具体容量和优先级是本轮建议。

| 范围 | 比赛 MVP 必需 | 留到以后 |
|---|---|---|
| 个性化 | 称呼、沟通风格、偏好、通知时间、自主权限 | 语音人格、动态头像、复杂角色系统 |
| 记忆 | 结构化长期记忆、来源、编辑、遗忘、跨会话恢复 | 大规模向量检索、自学习画像 |
| 目标 | 目标、期限、任务、依赖、完成标准、下一步 | 自动管理无限项目、复杂资源优化 |
| 主动性 | 云端 worker、内部计划更新、跟进、通知去重 | 全应用事件系统、任意外部行动 |
| 证据 | 单仓库 GitHub + 单项目 Vercel；自己的任务和用户补充 | 其他连接器、全仓库代码语义索引 |
| 接触入口 | 网页 + 企业微信自建应用，双向闭环 | 普通个人微信无条件直连、小程序、原生 App |
| 演示 | 通用目标 + 项目事实观察；公开隔离 Demo | 完整商业多租户平台 |

建议先支持一个真实使用者、至多三个活动目标，每目标约十个任务。公共 Demo 与真实空间隔离。上限用于控制成本和调试，不是长期产品限制。

## Proactive Contact

只为重要变化、用户决策、需要行动的跟进发消息；普通 commit 和同步仅更新 Evidence。Notification Service 与 WeChat Adapter 分离。企业微信为用户已接受的官方首版路线，实际客户端明确标注。原生按钮若不可用，保留消息链接到手机网页操作。

通知默认时段、合并窗口、稍后提醒等数值是待确认建议，见 PRD。失败的通知保留在网页收件箱并显示发送失败；网页提醒不能被描述为已经满足关闭网页后的微信触达。

## Later

个人生活习惯和家庭事项、资料整理、日历、邮件、知识笔记；部署修复建议与隔离检查；经用户逐步开放权限后的外部操作。

## Explicitly Cut

- 初始规划阶段已结束，用户已授权开发。购买服务的实际账户、规格与费用须有可核验依据。
- 首版不修改代码、不发布部署、不发第三方邮件、不提交比赛、不删除外部文件、不付款、不改外部日程。
- 首版不接 Calendar、Email、Notion、Slack、浏览历史，不开发通用浏览器控制。
- 不以 commit、文件存在或 CI 成功证明用户主观认可的“核心功能完成”。
- 不全量复制 Muse，不将单机容器部署称为具备任意代码执行能力的安全 Sandbox。
