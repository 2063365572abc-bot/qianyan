一次证据变化，怎样变成下一步？

个人管家把目标、偏好和当前计划存到数据库。独立Worker持续观察并核对事实，形成清楚的计划变化。模型负责提出方案；后端负责验证和提交。

跟着“部署失败”走三站

这是可自行查阅的路线，尚未进行用户参与的导览。样例使用带标签的回放，真实接入另需账户配置。

1 · 触发事件

frontend/src/App.tsx
搜索/demo/events。按钮发送回放事件；backend/app/main.py → demo_event写入持久任务。

2 · 核对与更新

backend/app/worker.py → observe加载证据。planning.py → evaluate_progress阻塞部署、创建排查任务、重新计算下一步。

3 · 看见结果

main.py → state读取当前任务、证据和Run。App.tsx → ResultBody把结果画成计划变化卡，样例通知只留在站内。

主要组件

  • frontend/src/：中英文工作台、手机布局、设置/目标/记忆/通知。
  • backend/app/main.py：鉴权后的API、版本校验、企业微信回调。
  • agent.py：个人上下文、Nemotron函数调用、预算预留、PlanPatch验证。
  • worker.py：后台任务领取与恢复、观察、跟进、通知Outbox。
  • planning.py：README结构、CI SHA、部署状态等完成规则。
  • db.py：PostgreSQL模型；adapters/：受限的外部API。
  • infra/compose.yaml：Caddy、API、Worker、迁移与数据库。

想改这里，从哪里开始

  • 页面文案和排版：App.tsx、styles.css。
  • 管家风格和默认通知窗口：schemas.py → ButlerSettings。
  • “README什么时候才算完成”：planning.py → readme_standard。
  • 主动跟进频率：worker.py → followup；免打扰：planning.py → next_contact。
  • 来源读取：adapters/github.py、adapters/vercel.py。这里不决定任务Done。

可复用的一条做法

先把“观察到进展”和“完成任务”分开，再写明确完成标准。tests/test_product.py → test_replay_closed_loop_and_dedup验证：README出现但缺安装内容时不能Done，重复部署失败不能重复建排查任务或通知。类似做法也适用于其他会自主维护状态的Agent。

重新运行

先按根目录README.md启动PostgreSQL并配置忽略的.env，分别打开三个终端：

cd backend
uv sync --frozen
uv run python -m app.migrate
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000

# 第二个终端
cd backend
uv run python -m app.worker

# 第三个终端
cd frontend
npm ci
npm run dev

打开http://localhost:5173。首次登录密码保存在忽略文件.local/access.json，不要发布。没有真实模型配置时页面会明确显示AI不可用。
