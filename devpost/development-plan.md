**整套方案已批准，当前进入开发与验证。** 用户已授权按本方案完成项目。实际进展与未验收事项见 [Build checklist](checklist.md)；服务器购买和真实账户接入以实测记录为准。

## 1. 推荐结论

做 **可定制的云端个人管家**：称呼、偏好、沟通方式、记忆和主动权限属于你；交代目标一次后，它在云端持续维护计划，并在必要时通过平台收件箱呈现跟进；企业微信接入暂缓。

开发顺序：**先完成管家底座 → 再接第一条自动观察场景 → 再扩展生活场景**。第一条验证用 GitHub + Vercel，因为能得到真实进度证据、能清楚演示自动重排，且只读风险低。生活目标可以先使用内部计划与用户补充；首版不声称自动感知线下生活。

推荐 Personal AI 赛道。原来通用 Coding Agent 与全量 Muse 克隆范围过大；本方案把长期存在和个人化落实为可验证闭环。完整六维候选对比见 [选题评估](idea-evaluation.md)。没有获奖保证，创新要靠产品中的可见差异证明。

## 3. 用户、痛点与完成标准

目标用户：希望拥有自己的个人管家、持续推进个人事项的人。第一条实际使用链是独立开发者/黑客松参与者，但内部模型不限于 coding。

痛点：目标需要反复解释；进度需手动维护；提醒不了解阻碍；聊天记录不能变成可信当前状态；用户忙时没有持续跟进。

完成标准：

1. 设置管家并交代一次目标，保存可编辑计划。
2. 下一次会话、次日、服务器重启后仍保留偏好、目标、历史进展和下一步。
3. 网页关闭期间后台实际运行，重新打开能看到有依据的计划变化与平台收件箱事项。企业微信手机触达属于后续阶段。
4. 回复或网页操作会改变内部计划，下一次跟进使用新状态。
5. 自动读取已连接系统的事实，带 Evidence 更新计划；证据不足不宣布完成。
6. 暂停、免打扰、纠正记忆、自主权限和数据隔离真正生效。
7. 评审能用公开链接体验核心逻辑，视频能看到真实系统闭环。

## 4. 功能优先级与难度

难度 1 最低、5 最高，为工程判断。P0 必须完成；P1 核心通过且有余量再做；P2 不进入比赛版。

| 模块 | 交付 | 优先级 | 难度 | 难点/边界 |
|---|---|---|---:|---|
| 个人化 | 称呼、风格、偏好、时区、通知、权限 | P0，先做 | 2 | 设置必须影响行为；风格不能越权 |
| 对话与目标 | 捕获目标、绝对期限、完成定义、初始计划 | P0，先做 | 3 | 模糊时间/目标需澄清，不能静默猜 |
| 持久记忆 | 来源、跨会话恢复、编辑、遗忘、导出 | P0，先做 | 3 | 旧记忆与摘要失效，避免新旧冲突 |
| 内部计划 | 任务依赖、优先级、下一步、用户纠正 | P0，先做 | 3 | 依赖无环、版本并发、撤销后仍尊重事实 |
| 云端主动性 | 常驻 worker、持久 job、到期跟进、重排 | P0，先做 | 4 | 重启恢复、幂等、不过度打扰 |
| 企业微信 | 向本人发送、接收回复、手机详情处理 | P0，早验证 | 4 | 账户、可信 IP、回调验签、投递失败 |
| Progress Evidence | 来源版本、完成规则、Unknown、结果卡 | P0 | 4 | 事实存在与满足完成标准分离 |
| GitHub 核心 | 单 Repo、commit/README/目录/指定 CI | P0，底座后 | 3 | SHA 对齐、权限、限流与 partial |
| Vercel 核心 | 单项目生产部署、失败、URL、状态观察 | P0，底座后 | 3 | Preview/Production、最新构建/旧线上区分 |
| 公开 Demo | 独立样例、英文切换、明确回放、真实模型 | P0 | 3 | 个人数据/微信权限隔离、成本控制 |
| GitHub 扩展 | Issue/PR、Release/Tag | P1 | 2–3 | 更多状态与映射规则；不是闭环前提 |
| 微信原生按钮 | 卡片内稍后/完成判断 | P1 | 3 | 官方具体类型与账户可用性；P0 使用网页链接 |
| 每日主动简报 | 用户明确订阅后的固定摘要 | P1 | 2 | 目前仅首页摘要，避免额外打扰 |

| Calendar/Email 等 | 新数据源和审批行动 | P2 | 4 | 授权、权限与更多外部影响 |
| Coding/浏览器行动 | 改代码、运行沙箱、部署、填表 | P2 | 5 | 不属于当前自主权限 |

## 5. 推荐技术架构

| 项 | 推荐 |
|---|---|
| Frontend | React + TypeScript + Vite，静态工作台，移动页面可用 |
| Backend | Python + FastAPI + Pydantic，产品 API、鉴权、回调 |
| Agent architecture | 单 Agent 显式状态机，工具白名单，模型提议 + 后端校验 |
| Persistent memory | PostgreSQL 结构化记忆/偏好/决定/摘要；可编辑、遗忘 |
| Repository understanding | GitHub API 只读进度切片、README 结构规则、SHA 对齐 |
| Code execution / sandbox | MVP 不运行仓库代码；后续开放检查时再接 Nebius Sandboxes |
| Nebius Token Factory | 运行时调用模型 API；实际模型 ID 与输出格式开发前实测 |
| NVIDIA Nemotron | 一个可用 Nemotron，建议 3 Super，真实承担拆计划和跟进 |
| Database / scheduler | PostgreSQL 数据与持久 job/outbox；独立 Worker，不增加 Redis |
| Notification | Notification Service → WeChat Adapter → 企业微信自建应用 |
| Deployment | 香港/新加坡 CPU VM + Docker Compose + Caddy HTTPS |
| Demo | 真实本人空间与隔离公共体验；回放有标签，真人视频展现真通知 |

每部分接口、数据表、拟建文件、失败处理和文档链接见 [Technical spec](spec.md)。服务器控制自己的数据库和偏好；模型推理仍需要向 Token Factory 发送必要上下文，不能宣传全部数据本机闭环。

## 6. 部署路线比较

| 路线 | 部署难度 | 常驻后台 | 企业微信可信出口 | 本次判断 |
|---|---:|---|---|---|
| **单台固定 IP CPU VM** | 3/5 | 独立 worker，直接控制 | 固定 IPv4 配置 | **推荐**；配置更多，成本/运行方式可控 |
| Railway Pro | 2/5 | 可部署 worker 和数据库 | Pro 提供固定出口，当前可能多个 IP 均需配置 | 运维更少的备选，基础费 $20/月，实际用量另核算 |
| Vercel 主托管 | 3–4/5 | 需拆成定时函数/外部后台 | 额外核验方案/费用 | 网页方便，完整持续管家配置更复杂；本次用于被观察项目 |
| Nebius Compute | 待账户核验 | 可按资源能力运行 | 按实际网络配置 | 已有资源可迁移；不假设账户能免费拿到适用规格 |
| 本地机器/临时隧道 | 2/5 起步 | 依赖电脑开机 | 回调和 IP 稳定性不足 | 本地开发可用，长期线上 Demo 不推荐 |

核验依据：[腾讯云公网网络](https://cloud.tencent.cn/document/product/1207/79254)、[企业微信官方配置](https://cloud.tencent.com/document/product/213/130517)、[Railway 固定出口](https://docs.railway.com/networking/static-outbound-ips)、[Railway 价格](https://docs.railway.com/pricing/plans)、[Vercel 函数限制](https://vercel.com/docs/functions/limitations)。难度评分和推荐属于本方案判断。

建议初始服务器目标 2 vCPU / 4 GiB、约 40–60 GiB 磁盘，无 GPU。实际可购套餐、计费和域名费用待购买前核验。**建议预留每月 30–60 美元开发/展示预算额度**，这是规划额度，不是报价；日模型预算和公开 Demo 限速必须做。Demo 至少保持到北京时间 2026-12-16 04:00，需计算后续托管费用。当前没有购买资源。

## 7. 工作量与开发顺序

预估单人、AI 辅助、范围固定的主动工程投入 **110–150 小时**，含必要调试/验证/材料，通常需要约四周、每周约 25–35 小时。用户经验/投入未确定，因此这是条件性工期，不能保证日历时间。以下日期按 2026-09-30 后及时开始计算；确认延迟需重排。

| 阶段 | 建议日期（北京时间） | 时间预算 | 可检查交付 |
|---|---|---:|---|
| 0 接入与运行验证 | 10-01–10-03 | 8–12h | Nemotron真调用；云端后台；企微真收发；GH/Vercel权限小检查 |

### 进度门槛

- **第3天**：真实模型、微信收发、常驻后台可用。企业微信不通优先解决账户/出口/回调；不先美化完整 UI。
- **10-11**：无连接器的通用管家闭环可用。偏好/目标跨会话保存，跟进和回复可改变计划。
- **10-20**：GitHub/Vercel真证据闭环；此后冻结 P0 新功能。
- **10-24**：有真实跨日记录，重启与公开隔离通过。
- **10-28**：材料全部可用，保留两天提交缓冲。

如果进度慢：先砍 P1、动画、复杂样式、全套授权、自动日志诊断；保留设置/记忆/目标/后台/微信/最小证据链。若关键 P0 仍缺失，必须明确缩减交付承诺，不能称完整管家已完成。

## 8. Demo 故事

用户把目标交代一次 → 管家按个人设置形成计划 → 关闭网页 → 系统观察 README 达标/部署失败 → 自动重排 → 企业微信通知 → 用户回复 → 次日保留上下文。另展示一次证据不足不武断完成，及修改个人偏好后新行为生效。

公开评审用独立样例空间和标记回放压缩等待；真人视频展示真实后台、真实外部来源和真实企业微信收发。公共体验不要求评审注册企微、不触达本人微信、不读取个人数据。实际 Nemotron推理保留于体验，预算受限时明确显示状态。

## 9. 当前未验证事项与风险

| 未验证事项 | 为什么影响完成 | 如何关闭风险 |
|---|---|---|
| 用户企微账户/管理员/成员可见范围 | 可能无法创建或使用应用 | 开发前确认资源；第0阶段真手机收发 |
| 微信回调/可信 IP/外链 | 必须后台可达和手机可处理 | 固定出口+HTTPS，官方协议测试与手机验收 |
| Token Factory模型/额度/schema | 目录可见不等于账户可调用 | `/models` + 小请求 + 结构校验，记录实际 model_id |
| Vercel状态/生产URL/日志权限 | 易误判最新构建与线上版本 | 只读真API样例，对齐target/alias/SHA |
| 真实投入与预算 | 直接决定Solo工期 | 确认范围后按投入重排；不默认免费/无限额度 |
| 长期使用效果 | 三分钟难证明“长期” | 保留真实跨日记录、关闭网页/重启证据 |

研究确认的是公开文档中的能力与规则；当前没有运行这些账户集成测试。风险处理详见 spec，不能把计划中可实现等同于现在已实现。
